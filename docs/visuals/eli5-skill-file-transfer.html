SYS-A → SYS-B · skill transfer

Think of it as a secure parcel delivery.

The skills are files inside a ZIP. Git carries the parcel; the bridge only tells the other machine where to collect it.

The packing station is built. The parcel has not left SYS-A yet.

1. What is inside the parcel?

Three pieces make the transfer safe and understandable.

ZIP = the parcel

18 Codex skills plus 8 required Agents mirrors.

Manifest = packing slip

It says exactly what should be inside and who should receive it.

SHA-256 = tamper seal

If even one byte changes, the seal no longer matches.

2. Two lanes do different jobs

The bridge is the messenger—not the moving truck.

🚚

Private Git carries the heavy parcel

The ZIP and packing slip live in one exact Git commit. SYS-B fetches that exact frozen snapshot.

📨

The bridge carries a tiny pickup message

It sends the commit ID, manifest path, expected seal, action, status, and receipt.

4. Is the infrastructure built?

Mostly—but “built locally” is not the same as “delivered end to end.”

Packing and checking

The release envelope, safe validator/installer, documentation, and 56 foundation tests are in place locally.

Road and messenger

The private Git remote exists. The bridge delivered the proposal message to SYS-B.

Actual delivery

No commit or push yet, no SYS-B acceptance yet, and therefore no real pinned install test yet.

Always-on automatic watcher

There is no unattended daemon that notices and installs skill parcels by itself. An agent runs the command.

Safe collision rule

If a skill already exists and is identical, accept it. If it differs, stop—never silently overwrite it.

Wrong-machine protection

Install refuses to run unless the receiving machine identifies itself as the intended target.
